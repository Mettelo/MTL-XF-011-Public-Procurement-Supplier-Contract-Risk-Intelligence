# Project Governance

## Engagement Classification

Mettelo Project Studio — simulated confidential-client engagement using official public/open data.

## Client Representation

Participants must not claim employment by or confidential access to the simulated client. They may accurately describe verified participation in Mettelo Project Studio and their evidenced contribution.

## Data Governance

Teams must document:

- source and provenance;
- data owner/publisher;
- extraction/version date;
- business glossary;
- critical data elements;
- quality rules;
- lineage;
- transformations;
- metric ownership;
- retention/reproducibility;
- limitations.

## Responsible Interpretation

Procurement notices are administrative records and do not by themselves prove supplier financial distress, poor performance, value for money or contractual risk. Teams must label analytical indicators appropriately and avoid unsupported supplier-risk claims.

## Decision Governance

No score, segment, forecast or prioritisation flag should be presented as an automatic organisational decision unless the evidence supports that interpretation. Teams must distinguish analytical indicators from policy, statutory, professional or executive judgement.

## GitHub Governance

The team repository must be created under the Mettelo GitHub organisation. Add each team member using their individual GitHub account. Use issues, branches, meaningful commits, pull requests and reviews where practical.

Never commit secrets, passwords, tokens, private credentials or prohibited personal information.

## Verification

Mettelo may inspect repository history, issues, PRs, reviews, tests, documentation, contribution evidence and final deliverables when verifying participation.
